# 采集管线与前端对接方案

日期：2026-09-12。范围：后端行为及前端对接建议；本轮不修改前端组件、布局或主题。

## 1. 新行为契约

- `helper.start()` 只执行「详情获取 → AI 分析 → 飞书入库」，沿用当前 BOSS 筛选结果和已有逐页读取行为。
- 采集不调用投递接口。旧 `autoDelivery` 配置即使为 true 也不会使采集自动发送；前端应移除/暂时隐藏该开关，而不是继续暗示它有效。
- 岗位名、公司、薪资、活跃度、已沟通等旧投递过滤条件只用于独立投递，不再造成采集漏项。采集范围由 BOSS 页面搜索和筛选决定。
- AI 的 APPLY / REVIEW / REJECT 都是正常分析结果；REJECT 仍入库。
- 未开启 AI / 飞书时，对应阶段记录为 skipped，不假装成功，也不误报失败。
- 开启 AI 时，简历/模型初始化错误会阻止整轮启动；开启飞书时，必要配置缺失也在启动前报错。此检查不等于远端凭据已验证。
- 飞书运行时失败：详情、分析结果保留；重试该岗位仅执行未成功阶段，不重复花费已成功的模型调用。
- `success` 现在表示「本次处理完成」，不等于「已投递」。采集不增加投递成功计数、不消耗投递限额。
- 投递为独立的单岗位操作，要求先完成详情和 AI 分析，遵守决策、过滤条件及投递上限；不支持采集结束后自动批量发送。
- 投递成功与飞书入库是两个独立事实，投递后不再重复调用同一入库任务。飞书里的用户维护求职进度仍不被本流程覆盖。

## 2. 前端读取接口

```ts
// 当前 BOSS 页面可见岗位；不代表全部已采集岗位。
helper.jobList.value

// 当前页面会话内跨翻页累积的岗位，含 jobData 和 state。
helper.jobMaps
helper.jobMaps.get(key)?.state.stages

// 顶层旧状态继续兼容；应结合阶段状态解释，不用它判断真实投递。
helper.jobResultMaps.get(key)
helper.currentJob.value
helper.workflow?.status.value
helper.workflow?.errorMessage.value
helper.workflowRunning.value // 同时覆盖整轮采集、单岗位重试、独立投递。

// 所有已发现岗位的分阶段汇总，每个计数键都存在，含 0。
helper.collectionSummary.value
// { total, stages: { detail, analysis, storage, delivery } }
// 每个阶段：{ pending, running, succeeded, skipped, failed, unknown }
```

每个岗位的 `state` 保留既有 `aiMatchResult`、`feishuRecordId`、`delivered`，并新增：

```ts
stages?: Partial<Record<'detail' | 'analysis' | 'storage' | 'delivery', {
  status: 'pending' | 'running' | 'succeeded' | 'skipped' | 'failed' | 'unknown'
  message?: string
  attempts: number
  startedAt?: number  // Unix 毫秒
  finishedAt?: number // Unix 毫秒
}>>
```

阶段缺失按 pending 展示；`delivery.pending` 应显示「未投递」，不要显示为采集流程未完成。

侧栏通过 `workflowBridge` 读取实时快照。`records` 含跨页累积岗位；`jobs` 仍为当前页；`summary` 为累计汇总；快照不包含原始页面对象、模型配置或密钥。业务页面使用 helper，不要重新实现通信。

## 3. 操作接口

| UI 动作 | 调用 | 约束 |
| --- | --- | --- |
| 开始采集 / 继续采集 | `await helper.start()` | 只采集，不发送；当前 BOSS 页就绪，设置需先保存 |
| 暂停 | `helper.stop()` | 阻止后续阶段；已发出的详情/模型/入库请求可能需要等待返回 |
| 重试该岗位 | `await helper.retryJob(key)` | 当前会话有该岗位且没有其他任务运行；复用成功阶段 |
| 重置旧顶层等待状态 | `helper.reset()` | 不清除成功阶段，不等于重新分析，不清空岗位库 |
| 确认投递该岗位 | `await helper.deliverJob(key)` | 必须由确认弹窗的确认按钮调用；不要绑定页面加载或采集完成事件 |

侧栏命令返回表示「操作已被页面接收」，不表示完整处理完成；真实完成以阶段快照为准。

底层独立投递命令要求 `{ command: 'deliver', key, confirmed: true }`。未确认、未知岗位、已有任务运行会拒绝。业务层不应自行绕过 helper 调用底层消息。

发送已成功或结果 unknown/running 时不重复发送。unknown 表示需要人工去 BOSS 核实，不能显示普通「重试投递」。本版本没有自动核实/解除 unknown 的 UI 接口。

## 4. 最小前端组件增量（PrimeVue 4 + Aura）

沿用现有工作台骨架、字体和 Aura 默认外观。只补能回答「做到哪一步、失败在哪、下一步怎么做」的信息，不新增自定义主题、装饰卡片或第二套组件库。

| 区域 | 官方组件 | 字段 / 交互 |
| --- | --- | --- |
| 运行操作区 | Button、Message | 主按钮改为「开始采集」；运行中「暂停」；固定说明「采集不会自动投递」；显示启动错误和设置入口 |
| 当前岗位阶段 | Timeline、Tag | 顺序显示详情、AI、飞书三阶段；每步显示状态，失败时展开 message；投递状态单独一行，不并入采集进度 |
| 本次会话汇总 | 简单文本布局、Divider | 发现 N / 详情成功 D / 分析成功 A / 入库成功 S；失败数另列，不用四个嵌套 Card |
| 岗位处理列表 | DataTable、Column、Tag、Button | 岗位/公司、详情、AI决策、飞书、操作；失败行显示「重试该岗位」；结果为 REJECT 不染成处理错误 |
| 失败详情 | Message 或 Accordion | 阶段名、错误 message、尝试次数；长文本折叠，不打印原始接口响应或凭据 |
| 单岗位投递 | Button、Dialog | 次级操作；确认框展示岗位、公司、AI决策和明确的发送影响；确认后调用 deliverJob；unknown 只提示到 BOSS 核实 |

不要使用可点击 Stepper：这些阶段是系统运行状态，不是用户可任意跳转的表单步骤。

### Tag 文案与 severity

| 状态 | 文案 | severity |
| --- | --- | --- |
| pending | 待处理；投递阶段为「未投递」 | secondary |
| running | 处理中 | info |
| succeeded | 详情已获取 / 已分析 / 已入库 / 已投递 | success |
| skipped | 未启用；投递被规则跳过时展示原因 | secondary |
| failed | 获取失败 / 分析失败 / 入库失败 | danger |
| unknown | 发送结果待核实 | warn |

### 宽窄屏处理

- 扩展宽屏：上方操作与汇总，中间当前岗位阶段，下方 DataTable。
- 原生 Side Panel：保留同一信息顺序；列表只显示岗位、失败阶段及操作，其余放在行展开区域。不要挤出横向滚动的七列表格。
- 空态区分「没有 BOSS 连接」「未发现岗位」「尚未开始」「AI 未启用」「飞书未启用」。不要统称暂无数据。
- 阶段无预估总量时不要伪造平滑百分比；逐页读取中的分母会变化，优先显示累计成功计数和当前岗位位置。

## 5. 前端验收样例

1. `autoDelivery=true` 的旧配置：开始采集仍零发送，页面明确写只采集。
2. AI=REJECT、storage=succeeded：显示「已分析 / 已入库 / 未投递」，不是失败。
3. detail、analysis 成功而 storage 失败：仅飞书阶段报错；重试后前两步计数与 attempts 不变。
4. AI 或飞书未启用：明确显示未启用，不出现错误红色，也不宣称已分析/已入库。
5. 暂停后：当前成功阶段保留，后续阶段待处理；不能显示已投递。
6. 关闭侧栏再打开：恢复同一个 BOSS 标签页的运行状态。页面刷新后的空状态不得伪装成恢复成功。
7. 点击投递但取消 Dialog：零发送；确认后失败为 unknown 时没有自动重试按钮。
8. 切换浏览器标签页：已连接侧栏仍指向原 BOSS 页，暂停不会发给另一页。

## 6. 本版本限制与下一步

- 进度和阶段缓存仍限当前 BOSS 页面会话；不是跨浏览器重启、页面刷新可恢复的持久任务库。
- 成功阶段在失败重试时复用原结果。修改简历、模型或飞书目标不会自动重跑已完成岗位；本版本不提供强制重新分析接口。
- 投递结果 unknown 需要人工核实；不承诺跨页面刷新后的绝对去重。
- 真实网站、模型与飞书端到端验证应使用小量岗位并确认目标设置；本轮自动化测试使用模拟外部接口，不代表真实入库/投递已完成。
- 前端 Agent 先接入运行区、三阶段状态和失败重试；单岗位投递 UI 最后接入并单独验收。四项工程检查通过仍不等于用户视觉验收。
