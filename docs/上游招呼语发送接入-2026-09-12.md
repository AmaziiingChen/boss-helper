# 上游招呼语发送接入

## 实现范围

复用上游 `12ff171` 的聊天连接方式与 `geek-chat-core.ts` Protobuf schema，仅保留当前需要的文字编码和业务回执解码。未恢复旧 Nuxt UI，也未复制整个压缩聊天 SDK。悬浮确认窗沿用 PrimeVue 4 / Aura，位于当前侧栏，不跳转 BOSS 消息页。

入口：岗位详情 → 生成或编辑招呼语 → 审核并发送 → 核对公司、岗位、招聘人、原文及默认招呼语关闭状态 → 确认发送这一条。仅此按钮触发发送；采集、AI 生成、保存草稿均不联系 HR。不发送附件简历，不自动回复后续消息，不批量发送。

## 发送契约

- 保留现有 AI 决策门槛（APPLY，或允许投递的 REVIEW）。启用飞书时发送前重新读取唯一岗位记录，只有求职进度为“待处理”才继续，不修改求职进度或新增字段。
- 页面拥有执行权；侧栏经 `sendGreeting` 桥传递明确确认的单个岗位与原文，仍绑定原 BOSS 标签页。运行中拒绝并行采集或另一次发送。
- `getBossData` 使用目标岗位的 `encryptBossId`，不再误用求职者账号 ID。返回的 `encryptBossId`、`encryptJobId` 均须匹配，数值收件人 ID 必须精确且不能是本人。
- 新会话先建立沟通关系，再获取收件人数值 ID 并发送；由于非好友关系可能无法读取完整招聘人数据，该校验位于建立关系之后。因此后续检查失败时可能已建立关系，但不会发送文字，界面必须区分两者。
- 每次发送具有独立 `clientMid`。只有匹配 `type=5 / messageSync.clientMid` 且包含有效 `serverMid` 的业务回执才能标记文字发送成功，不以 MQTT publish 回调或固定等待时间代替。
- 使用单次连接与单次 publish，`retain=false`、`qos=0`、`reconnectPeriod=0`、`queueQoSZero=false`。不自动重连、排队或重发；结束后释放连接。当前 BOSS 服务兼容性仍需真实单条验收。
- 本地发送记录在外部变更之前保存，按当前账号和招聘人去重；同源 Web Locks 防止不同 BOSS 标签页同时联系同一招聘人。持久化失败则不发起外部变更。
- 超时、断线、外部请求后失败或成功回执后的存储失败均为“待核实”，不提供自动重试。浏览器清除扩展存储、不同浏览器配置或平台外人工发送不在此去重边界内。
- 本地记录仅保存文本摘要、消息编号、阶段和结果；不写入 token、Cookie、完整简历或消息原文。已保存草稿仍遵循原有本机草稿存储规则。

## 文件

- `src/entrypoints/boss/chat/`：上游协议编码及单次发送/ACK 处理。
- `src/services/greetingSend.ts`：持久化意图、关系状态、文字状态及失败分类。
- `src/entrypoints/boss/greetingSend.ts`：当前 BOSS 账号、收件人校验、跨标签锁与接口调用。
- `src/components/AI/GreetingDraft.vue`：生成、编辑、悬浮确认与结果展示。
- `src/message/workflowBridge.ts`、`sidepanelWorkflow.ts`、`boss-page.content.ts`：单岗位发送命令和状态回传。

## 依赖

新增固定版本：`mqtt@5.15.2`（MIT）、`protobufjs@8.8.0`（BSD-3-Clause）、`buffer@6.0.3`（MIT）。来自 npm 官方 registry，沿用项目 `bun.lock`。上游代码许可证沿用仓库 MIT / Ocyss 声明。未新增全局依赖或第二套 UI 库。

## 验证与边界

模拟测试覆盖正文确认、收件人匹配、账号隔离锁、存储失败、AI/飞书门槛、关系与文字区别、ACK 匹配、64 位 ID、断线超时及阻止重复发送。Chrome 本地模拟页使用实际组件检查了 360px / 600px 布局、默认禁用确认、发送中锁定和模拟成功后防重；结果放在固定操作区，避免小窗口滚动后看不到状态。

Chrome 扩展构建使用隔离输出，未覆盖或重载用户正在执行采集的扩展。当前真实 BOSS 页面只读核验过默认招呼语关闭及聊天输入区；本次没有真实发消息、创建新沟通关系、修改 BOSS 设置或写入飞书。模拟通过不等于当前 BOSS 发送协议和真实业务已验收。

下一步真实验收需在采集结束后加载新构建，并由用户指定一个目标招聘人和明确批准的原文；只发送一条并核对 BOSS 业务回执和消息页，不以“建立沟通关系”冒充文字送达。
