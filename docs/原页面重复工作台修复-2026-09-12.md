# BOSS 原页面重复工作台修复

## 原因与修改

原页面脚本仍注册 `boss-helper-job` 并在 BOSS 缺少旧右侧栏时插入主内容区，同一 App 又在原生侧栏显示，造成重复工作台和无样式长列表。

- `src/index.ts` 不再创建 Vue App、Shadow DOM 或注入样式，只加载保存的配置/模型并初始化数据绑定。
- `src/entrypoints/boss/index.ts` 不再插入内嵌工作台、不再修改右侧栏宽度或删除原站节点；移除仅服务于旧 UI 的路由重挂载回调。
- 保留岗位数据绑定、快照与操作通信、原生侧栏入口，未调整采集或投递契约。

## 验证

- 新增 3 项测试：无 DOM 环境下启动、初始化失败不绑定、重复挂载请求只初始化一次且不访问页面布局 DOM。
- 当前工作树全套 96 项契约测试通过（包含已有飞书改动的测试）；lint、typecheck、diff check 通过。
- Chrome 构建报告 Finished；生成 `.output/chrome-mv3`。既有 import.meta 警告保留，构建完成后的驻留进程手动结束。
- 构建的 `boss.js` 不再包含 `boss-helper-job`、`ph-shell`、`本次会话岗位` 等工作台标识。
- 已有测试 Chrome 的 360px 侧栏模拟交互 15 项通过，并检查截图。未调用真实模型、飞书写入或 BOSS 发送。
- 用户实际 BOSS 页面尚未现场复验：Tabbit 无目标标签页，原生浏览器读取超时。需要重新加载扩展并刷新 BOSS 页面后核对红框消失、原岗位列表正常、侧栏仍能读取岗位。

## 生效与范围

先停止运行中的采集，待请求结束后重新加载扩展，再刷新 BOSS 页面并重开侧栏。刷新会清空当前页面会话记录。

现有飞书相关未提交修改未被覆盖。本修复未提交 Git；构建来自完整当前工作树，并非只包含本修复。
